# 快捷键：为什么只能「显示」，改要去浏览器自己的页面

> **这一篇讲的是 Chrome / Edge。** Firefox 其实支持 `commands.update()` / `commands.reset()`
> （扩展可以自己改快捷键），只是归拢没走那条路 —— 三家共用一套「显示 + 跳转」的行为更省事。

**Chrome 的 `commands` API 只能读、不能写。** `commands.update()` 和 `commands.reset()` 是 Firefox 才有的东西；Chrome 这边扩展**没有任何办法**设定或修改自己的快捷键。所以设置里那一行能做的只有两件事：把浏览器当前绑好的组合读出来显示，再给一个按钮跳到浏览器的快捷键设置页。在那个页面上你可以录任何组合 —— 那才是「自由修改」真正发生的地方。

跳转地址由 `extension/env.js` 给：Chrome / Edge 是 `chrome://extensions/shortcuts`，Firefox 是 `about:addons`。

三条硬规则，知道了就不会白试：

- **组合里必须有一个 `Ctrl` 或 `Alt`**（macOS 上 `Command` 也算；在 mac 上写 `Ctrl` 会被 Chrome 自动转成 `Command`）。
- **合法按键只有**：`A`–`Z`、`0`–`9`、`Comma`、`Period`、`Home`、`End`、`PageUp`、`PageDown`、`Space`、`Insert`、`Delete`、四个方向键、四个媒体键。所以 **`⌘+\` 这种用反斜杠的组合注册不了** —— 不是这里没做，是 Chrome 压根不认这个键。冒烟测试里有一条白名单断言盯着这件事。
- 组合被浏览器自己的功能占用时（比如窗口管理那批 `Ctrl+Shift+数字`），扩展抢不过来。

⚠️ **Firefox 上默认键是 `Ctrl+Shift+L` 不是 `K`** —— `Ctrl+Shift+K` 在 Firefox 里是「Web 控制台」，撞车了。这个替换是打包脚本在生成 Firefox 包时做的（`tools/build-store.js`）。

⚠️ 还有个容易白忙半天的坑：**改 `manifest.json` 里的默认键，点「刷新」不一定生效**，Chrome 往往要等到重新加载扩展时才重新分配。而「移除再重载」会把 `chrome.storage.local` 一起清掉（钉住的站点、稍后再看全没）。所以**默认值只是个建议，真要改就直接在那个页面上改**。

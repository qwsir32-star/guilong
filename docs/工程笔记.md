# 工程笔记

长篇的东西都在这儿。README 只放一眼能看完的部分。

## 工作方式

```
你打开一个新标签页
  -> 页头下面是天气和今天的气温（拿本地缓存先画出来，不为网络等一秒）
  -> 归拢把你开着的标签页按域名摆出来
  -> 主页类站点（Gmail、X 等）单独一组放在最前
  -> 点任意标题跳过去
  -> 看完了的整组关掉（音效 + 彩带）
  -> 舍不得关的先存入「稍后再看」
```

所有逻辑都跑在扩展里。没有服务器、没有账号。稍后再看、钉住的站点、天气城市与设置都存在 `chrome.storage.local`。唯一一次对外请求是取天气（可关），它只发城市坐标，不带你任何浏览数据。

## 技术栈

| 部分 | 实现 |
|------|------|
| 扩展 | Manifest V3（Chrome / Edge / Firefox 三家） |
| 存储 | `chrome.storage.local` |
| 音效 | Web Audio API（运行时合成，不带任何音频文件） |
| 动画 | CSS transition + JS 粒子彩带 |
| 界面文案 | `strings.js` 里的单张 `STRINGS` 表 + `T()` / `Tn()` 取词 |
| 构建 | **无**。`extension/` 目录直接 load unpacked 就能跑 |

想上架商店时才需要打包：`node tools/build-store.js`（见下）。

## 扩展 ID：`manifest.json` 里的 `key` 字段是干什么的

**这一行别删。** 它把 Chrome 的扩展 ID 固定住了。

Chrome 给「加载已解压的扩展程序」分配的 ID，在 manifest 没有 `key` 字段时，是**由 `extension/` 文件夹的绝对路径算出来的**。也就是说：**你把仓库换个目录、改个名字，ID 就变了。** 而 `chrome.storage` 是按扩展 ID 分目录存的，于是你钉住的常用站点、「稍后再看」里的条目、设置开关会通通读不到 —— 数据并没有被删，只是换了抽屉，但表现出来就是「全没了」。

有了 `key`，扩展 ID 就和路径无关：随便挪、随便改名、换台机器 clone 下来，都是同一个 ID。`tests/smoke.js` 里有一条守卫专门盯着这个字段，删掉会立刻变红。

> 这对密钥是用下面两行生成的，记录在此以备将来重新生成：
>
> ```bash
> openssl genrsa -out key.pem 2048
> openssl rsa -in key.pem -pubout -outform DER | openssl base64 | tr -d '\n'
> ```
>
> 公钥（一长串 `MII...`）公开无妨，写进 manifest 即可。**私钥不要提交到仓库** —— 只有打包 `.crx` 时才用得上，而这个项目直接 load unpacked，用不到它。

⚠️ 打包时 Firefox 那份会**删掉 `key`**（Firefox 不认这个字段），改用 `browser_specific_settings.gecko.id` 固定 ID。

## 打包：一家源码，三个包

```bash
node tools/build-store.js
```

Chrome 和 Edge **共用同一个包**（Edge 是 Chromium，`chrome.*` 全对齐）。Firefox 只改 manifest，代码一行不动 —— 前提是只用三家都有的 API，这点我们做到了，差异全在 `extension/env.js` 里。

Firefox 那一份做了四处变换：

1. `background.service_worker` → `background.scripts`（Firefox 的 MV3 用 event page，没有 service worker）
2. 加 `browser_specific_settings.gecko.id`（MV3 签名必填）+ `strict_min_version: "142.0"`
3. 加 `data_collection_permissions: { required: ["none"] }` —— 2025-11 起 AMO 对所有新扩展的硬性要求，不写 `web-ext lint` 直接报 `MISSING_DATA_COLLECTION_PERMISSIONS`
4. 删 `key` 和 Chromium 专有的 `favicon` 权限；默认快捷键换成 `Ctrl+Shift+L`（`K` 在 Firefox 里是 Web 控制台）

版本地板 142.0 是**算术**不是拍脑袋：根证书过期要求 ≥115 ESR / 128，后台双键要求 ≥121，`data_collection_permissions` 要求桌面 ≥140 / Android ≥142 —— 取 142 三个都过。

⚠️ 打包脚本每条改动都带断言，**有一条没过就不打这个包**。宁可打不出来，也不打一个错的上去。

## 测试

```bash
node tests/smoke.js
```

没有依赖、不联网、一秒内跑完。

它做三件事：用最小 stub 把 `app.js` 装进 Node 的 `vm` 里，直接调用内部纯函数验证行为（子域归并、去重、入口 URL 归一化、TLD 剥离、占位图识别、设置项默认值、天气码映射、缓存新鲜度、搜索失败与「没搜到」的区分、跨浏览器的地址与 API 判定……）；给网络和图片做受控的假环境，把各种失败路径一个个造出来；再对源码做静态扫描，守住几条约定 —— 界面文案必须走 `strings.js`、页头版式的不变量、旧品牌名不许回流、天气不许偷偷加权限、源码里不许写死任何一家的 `chrome://` 地址。

一共 **400 多条断言**，一秒内跑完。

**它不点界面**，也不验证真实浏览器 API 的行为，所以它不能替代你手动加载扩展看一眼。它守的是「逻辑 + 源码约束」，不是端到端。

每条守卫都做过**变异测试**：故意把它对应的代码改坏，确认测试真的会变红。一条永远不会失败的断言不是守卫，只是装饰。

## 个性化：`extension/config.local.js`

有些东西只跟你的使用习惯有关，不该混进源码。在 `extension/` 下新建 `config.local.js`（已在 `.gitignore` 里，不会被提交）：

```js
// 把「主页」判定扩到你自己常去的那些站
// 默认规则只认内置几个（Gmail / X / GitHub / YouTube / LinkedIn）
const LOCAL_LANDING_PAGE_PATTERNS = [
  { hostname: 'mail.qq.com' },                        // 只看这个域的根路径
  { hostnameEndsWith: '.example.com', pathPrefix: '/dashboard' },
];

// 自定义分组：把子域并成一张卡，或者按路径拆开
const LOCAL_CUSTOM_GROUPS = [
  { hostnameEndsWith: '.example.com', groupKey: 'example', groupLabel: '示例全家桶' },
];
```

这两组规则的**优先级都高于内置规则**，可以覆盖内置的子域合并逻辑。文件不存在也完全没关系 —— 扩展照常用内置默认值跑，只会在控制台留一条无害的 404。

**匹配字段速查**

- `LOCAL_LANDING_PAGE_PATTERNS`：`hostname` 或 `hostnameEndsWith`（二选一）+ 可选的 `pathExact`（数组）、`pathPrefix`、或自定义函数 `test(pathname, url)`。**都不给路径条件时，只匹配该域的根路径 `/`**。
- `LOCAL_CUSTOM_GROUPS`：`hostname` 或 `hostnameEndsWith` + 可选的 `pathPrefix`，另需 `groupKey`（并组用的 key）和 `groupLabel`（卡片上显示的名字）。

## 想换图标

图标母版是 `extension/icons/icon.svg`，`icon16 / 32 / 48 / 128.png` 全部由它导出 —— **改图标只改这一个文件**，然后重跑一次导出脚本：

```bash
cd tools && npm i && cd ..    # 只装这一次；依赖关在 tools/ 里，仓库根目录不会被 package.json 污染
node tools/make-icons.js
```

脚本会顺手核验每张 PNG 的实际尺寸和文件名是否对得上，对不上就报错退出。这一步只在改图标时才需要 —— **平时加载扩展不需要任何构建**。

⚠️ 有一条约束值得知道：**16px 是这个图标真正的战场，不是 128px。** 细线条和窄缝在那个尺寸下会整片消失（五根细签会糊成一条实心条），所以图形必须画得够粗、缝留得够宽。改完一定要看 16px 那张。冒烟测试里有一条守卫会检查 `manifest.json` 声明的每个图标文件都存在、且实际像素尺寸和声明一致。

# 浏览器测试

测试分为两层：`tests/smoke.js` 等脚本检查逻辑和文件约定；`tools/check-browser.js` 在真实浏览器中安装扩展、操作页面，并检查浏览器中的标签页与本地存储。

## 最近实测

2026-09-22，扩展 1.5.4，macOS 15.7.3 / Apple Silicon：

| 浏览器 | 实测版本 | 核心操作 |
|---|---|---|
| Chrome | 153.0.8010.53 | 10 项通过 |
| Edge | 153.0.4234.48 | 10 项通过 |
| Firefox | 156.0 | 10 项通过 |

Chrome 和 Edge 还通过了干净源码的 6 个首装场景：中文、英文、小窗口、窄窗口、断网和新标签页。

Windows 在 GitHub Actions 的独立测试机上运行同一套核心测试，结果见[真实浏览器测试](https://github.com/qwsir32-star/guilong/actions/workflows/browser-test.yml)。是否通过以具体运行记录为准；不能用 Mac 的通过结果代替 Windows 实测。

## 核心操作覆盖范围

1. 原生新标签页入口显示归拢，样式正常。
2. 不同站点分组，工具栏角标随真实标签页数量更新。
3. 点击去重后，同一网址只保留一份。
4. 点击保存、归档和恢复，实际标签和本地清单正确变化。
5. 点击标题能定位另一个窗口中的标签页。
6. 设置窗口开关正常，连续修改语言和主题都能保留，常用站点能保存。
7. 页面重新加载后，保存清单、主题、语言和常用站点仍在。
8. 整组关闭先确认，第二次才关闭，其他分组不受影响。
9. 浏览器实际注册了呼出快捷键。
10. 退出浏览器后重启、重新加载测试扩展，保存清单和设置仍在；Firefox 同时验证临时扩展未自动保留。

## 本地运行

需要 Node.js 22 或以上，以及实际安装的目标浏览器。下面是 macOS / Linux shell 的写法：

```bash
# Chrome：macOS 默认路径可直接使用
node tools/check-browser.js

# Edge：替换成实际可执行文件路径
GL_BROWSER=edge GL_BROWSER_BIN="/Applications/Microsoft Edge.app/Contents/MacOS/Microsoft Edge" node tools/check-browser.js

# Firefox：先生成对应配置；自动化测试要求 Firefox 148+ 的窗口调试接口
node tools/build-store.js
GL_BROWSER=firefox GL_BROWSER_BIN="/Applications/Firefox.app/Contents/MacOS/firefox" node tools/check-browser.js
```

Windows PowerShell 示例（Chrome）：

```powershell
$env:GL_BROWSER = 'chrome'
$env:GL_BROWSER_BIN = "$env:ProgramFiles\Google\Chrome\Application\chrome.exe"
node tools/check-browser.js
```

脚本自动创建临时浏览器配置和本地测试网页，使用完会关闭测试进程并清理配置，不使用个人浏览器资料。报告输出到 `dist/browser-check/<浏览器>/report.json`；Chrome / Edge 还输出截图。可以用 `GL_EXT` 指定待测扩展目录，用 `GL_OUT` 指定报告目录。

Firefox 自动化需要的调试参数仅用于测试进程，普通用户按安装指南加载即可。

## 结论的边界

- 这些是无界面浏览器自动化测试，UI 操作用页面点击事件驱动；不能替代安装对话框和视觉交互的人工验收。
- Chrome / Edge 通过调试协议安装的测试扩展具有临时性质，重启测试会重新加载。它验证数据保留，不证明手动安装的扩展在每种系统策略下都自动保留。
- 快捷键检查的是实际注册结果；没有完整验证操作系统级按键冲突和真实工具栏鼠标点击。
- Firefox 的调试协议不支持扩展页面截图，因此未生成 Firefox 视觉验收截图。
- 不代表所有浏览器历史版本、企业管控电脑、Linux、Windows 桌面版本都已验证。

## 本轮发现并修复的问题

- 干净源码缺少可选的 `config.local.js`，原来每次打开新标签页都会请求不存在的脚本。现在只在文件存在时加载，保留个人规则的能力。
- 同时修改两项设置可能相互覆盖。现在按顺序完成读写。
- 整组关闭原来第一次点击就执行，与说明不符。现在复用二次确认逻辑。

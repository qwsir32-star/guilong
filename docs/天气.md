# 天气：数据从哪来，以及它为什么不问你要权限

天气是归拢唯一会往外网伸手的地方，所以这里把话说明白。

**用的是 [Open-Meteo](https://open-meteo.com/) 的预报接口**（坐标 → 实况）。

选它的理由，按重要性排：

1. **免费，而且不要 API key。** 要 key 的方案意味着每个用的人得自己去注册一个、填进配置里；这个项目只是个小扩展，不该把「让你的天气能用」变成一件差事。
2. **它不需要任何新权限。** 这是最要紧的一条，见下。

## 搜城市为什么不打接口：答案不在接口的数据里

曾经用过 Open-Meteo 的地理编码接口（城市名 → 坐标）。实测对中国地名基本不可用：**搜「青岛」返回 3 条（辽宁的青岛村 + 两个无人岛），真正的青岛市根本不在结果里**；搜「大连」5 条全是村子；搜「山东」10 条全是村子，山东省本身一条都没有。

正确答案不在数据里，任何筛选规则都救不了。所以城市搜索改走**本地城市库**（`extension/china-places.js`，`tools/make-china-places.js` 从阿里云 DataV 行政区划数据生成，adcode 为准）：

- **只收省 / 市两级**正经行政区 —— 普通省、自治区到地级市，直辖市到区，香港、澳门、台湾到自身；
- 搜「青岛」只会出青岛市，搜「朝阳」出两个但两个都是真的（朝阳区 · 北京市 / 朝阳市 · 辽宁省）；
- 选个省（比如「山东」）就给省会的天气 —— 这是人搜省时最可能的意图；
- **搜索完全离线**，不打网络、不会超时、没有「搜不动」这种失败。

代价：国外城市选不了。这是定下来的框架（中国省、市两级），不是 bug。

## 为什么加一个联网功能，却不用加 `host_permissions`

浏览器扩展要在页面里跨域取数据，通常得在 `manifest.json` 里声明 `host_permissions`。**但这里有更要紧的东西**：一旦声明了新权限，用户下次重载扩展时会看到一个确认框，措辞是「读取您在所有网站上的数据」那个级别 —— 对一个只想显示气温的功能来说，这个代价太大。

而 Open-Meteo 的响应头里带着 `access-control-allow-origin: *`。也就是说扩展页可以直接按普通 CORS 请求取到它，**一个权限都不用加**。这一点是实测过的（带着 `Origin: chrome-extension://...` 问过一遍），不是推测。冒烟测试里有一条断言专门守着 `host_permissions` 不许出现。

代价是：**没有权限做兜底**。哪天这个 CORS 头没了，请求就会失败 —— 而且是静默失败。所以失败路径必须做干净。

## 发出去的到底是什么

只有一样东西：**你选的城市坐标**（默认上海：北纬 31.22222、东经 121.45806）。就两个数字。

城市搜索是本地的（见上），你敲进搜索框里的字**不出你的机器**。

**没有**标签页数据、没有浏览历史、没有设备标识、没有 cookie、没有账号。请求里不带任何能认出你的东西。想彻底不发，把设置里的天气开关关掉就行。

## 拿不到数据的时候会怎样

这是这个功能设计上最花心思的地方：

- **不报错、不弹提示条、不删缓存。** 断网、被墙、接口挂了，你在新标签页上看到的只是「这里没有天气」，而不是一个看不懂也修不了的红条。新标签页是最不该出现错误提示的地方。
- **缓存优先。** 结果缓存在本地 20 分钟。打开新标签页时先用缓存立刻画出来，缓存新鲜就一次网络都不打，过期才去回源。所以打开新标签页这个高频动作不会被网络拖住。
- **缓存永不主动删。** 过期只是让它重新拉一次；拉不到就继续显示旧的那份，总比空着强。
- **换城市会丢掉旧城市的缓存。** 不丢的话，页面会拿上海的 26° 配上你新选的「北京」显示出来 —— 看着一切正常，但它是错的，而且不报任何错。
- **形状不对就当没拿到。** 接口返回的温度如果不是数字，宁可什么都不显示，也不画一个 `0°` 或 `NaN°` 上去 —— 那种错看起来像真的。

## 天气图标

7 张（晴 / 晴间多云 / 阴 / 雾 / 雨 / 雪 / 雷雨），全部用圆、矩形、直线拼出来，**没有抄任何弧线路径** —— 小尺寸下能靠自己把图元算出来长什么样，而不是赌一段没法验证的 `d` 属性是对的。每一张都在 16px 真渲染出来看过。接口给的 28 个 WMO 天气码被归成 11 类，强度差别（毛毛雨 / 中雨 / 大雨）抹平了：那一行字没有那么大地方，而「外面在下雨」这个信息量已经够决定要不要带伞。

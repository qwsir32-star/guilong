# 归拢

**散着的标签页，归拢一下。**

归拢接管你的新标签页：把你此刻开着的所有标签页按域名摆成一张网格仪表盘 —— 哪个站开了多少个、哪些其实开重了、哪些只是"先放着回头再看"，一眼扫完。关掉的时候有音效和彩带。

没有服务器、不用账号、不需要任何 API key。除了取天气那一次请求，你的数据一个字节都不出机器。

> **衍生说明**：本项目是 [Tab Out](https://github.com/zarazhangrui/tab-out)（作者 [Zara](https://x.com/zarazhangrui)）的衍生版，在其基础上做了中文化与若干增强。原项目采用 MIT 许可证，原始署名与许可证原文都完整保留在 [LICENSE](./LICENSE) 中。

## 安装

**1. 克隆仓库**

```bash
git clone https://github.com/qwsir32-star/guilong.git
cd guilong
```

**2. 加载扩展**

1. 打开 Chrome，地址栏输入 `chrome://extensions`
2. 打开右上角的**开发者模式**
3. 点左上角的**加载已解压的扩展程序**
4. 选中仓库里的 `extension/` 文件夹

**3. 打开一个新标签页**

你会看到归拢。

> **改完代码记得这样做**：新标签页有缓存，只点扩展卡片上的刷新按钮不一定生效，要**关掉旧的新标签页重新开一个**。另外扩展需要 `topSites` / `favicon` / `search` 三项权限，重载时 Chrome 可能让你再确认一次。

### 关于扩展 ID：`manifest.json` 里的 `key` 字段是干什么的

**这一行别删。** 它把扩展 ID 固定住了。

Chrome 给「加载已解压的扩展程序」分配的 ID，在 manifest 没有 `key` 字段时，是**由 `extension/` 文件夹的绝对路径算出来的**。也就是说：**你把仓库换个目录、改个名字，ID 就变了。** 而 `chrome.storage` 是按扩展 ID 分目录存的，于是你钉住的常用站点、「稍后再看」里的条目、设置开关会通通读不到 —— 数据并没有被删，只是换了抽屉，但表现出来就是「全没了」。

有了 `key`，扩展 ID 就和路径无关：随便挪、随便改名、换台机器 clone 下来，都是同一个 ID。`tests/smoke.js` 里有一条守卫专门盯着这个字段，删掉会立刻变红。

> 这对密钥是用下面两行生成的，记录在此以备将来重新生成：
>
> ```bash
> openssl genrsa -out key.pem 2048
> openssl rsa -in key.pem -pubout -outform DER | openssl base64 | tr -d '\n'
> ```
>
> 公钥（一长串 `MII...`）公开无妨，写进 manifest 即可。**私钥不要提交到仓库** —— 只有打包 `.crx` 时才用得上，而这个项目直接 load unpacked，用不到它。

## 功能

| 功能 | 说明 |
|---|---|
| **一眼看尽** | 打开的标签页按域名分组，网格排开 |
| **主页单独成组** | Gmail 收件箱、X 首页、YouTube、LinkedIn、GitHub 主页收进一张卡片，一次关干净 |
| **关得爽** | 关闭时合成音效 + 粒子彩带 |
| **重复检测** | 同一个页面开了两遍会被标出来，可一键清理 |
| **点标题就跳** | 点任意标签页标题直接跳过去，跨窗口也行，不会多开一个 |
| **存入稍后再看** | 关之前先把想留的存进清单 |
| **本地项目分组** | `localhost` 后面显示端口号，几个项目分得清 |
| **可展开的分组** | 每组先显示前 8 个，其余折叠在「还有 N 个」后面 |
| **常用站点条** | 常去的站点钉在顶部，可按住拖动排序；点一下永远是新开一个标签页 |
| **站点图标** | 默认用 Chrome 自己缓存的那份 favicon；也可以在「图标」里填图片地址，或者填 1–2 个字当文字图标 |
| **搜索框** | 输入网址就直接打开，否则交给你自己设的默认搜索引擎（不替你做主） |
| **设置开关** | 「常用站点条」和「搜索框」可以各自关掉 —— 只控制显示，钉过的数据一条不删 |
| **工具栏图标** | 点扩展图标就把仪表盘叫出来（已经开着就切过去，不会开第二个）；图标角标显示当前标签页数，绿 / 黄 / 红三档 |
| **呼出快捷键** | 一键打开归拢；默认 `⌘⇧K` / `Ctrl+Shift+K`，设置面板里能看到当前绑定，并能跳到 Chrome 的页面改成任何组合 |
| **当地天气** | 页头下面一行：图标 + 气温 + 城市 + 今天的最高最低。城市在设置面板里搜着选，默认上海；可以整个关掉 |
| **归档** | 处理过的分组可以归档，之后还能搜回来 |
| **中英双语** | 默认中文，全部界面文案集中在 `strings.js` 一张表里 |
| **数据本地** | 标签页数据、钉住的站点、稍后再看、设置全在 `chrome.storage.local`，不往任何服务器发。唯一的对外请求是天气（见下） |

### 快捷键：为什么只能「显示」，改要去 Chrome 自己的页面

**Chrome 的 `commands` API 只能读、不能写。** `commands.update()` 和 `commands.reset()` 是 Firefox 才有的东西；
Chrome 这边扩展**没有任何办法**设定或修改自己的快捷键。所以设置里那一行能做的只有两件事：把 Chrome 当前
绑好的组合读出来显示，再给一个按钮跳到 `chrome://extensions/shortcuts`。在那个页面上你可以录任何组合 ——
那才是「自由修改」真正发生的地方。

三条硬规则，知道了就不会白试：

- **组合里必须有一个 `Ctrl` 或 `Alt`**（macOS 上 `Command` 也算；在 mac 上写 `Ctrl` 会被 Chrome 自动转成 `Command`）。
- **合法按键只有**：`A`–`Z`、`0`–`9`、`Comma`、`Period`、`Home`、`End`、`PageUp`、`PageDown`、`Space`、
  `Insert`、`Delete`、四个方向键、四个媒体键。所以 **`⌘+\` 这种用反斜杠的组合注册不了** —— 不是这里没做，
  是 Chrome 压根不认这个键。冒烟测试里有一条白名单断言盯着这件事。
- 组合被 Chrome 自己的功能占用时（比如窗口管理那批 `Ctrl+Shift+数字`），扩展抢不过来。

⚠️ 还有个容易白忙半天的坑：**改 `manifest.json` 里的默认键，点「刷新」不一定生效**，Chrome 往往要等到
重新加载扩展时才重新分配。而「移除再重载」会把 `chrome.storage.local` 一起清掉（钉住的站点、稍后再看
全没）。所以**默认值只是个建议，真要改就直接在那个页面上改**。

## 天气：数据从哪来，以及它为什么不问你要权限

天气是归拢唯一会往外网伸手的地方，所以这里把话说明白。

**用的是 [Open-Meteo](https://open-meteo.com/)**，两个接口：地理编码（城市名 → 坐标）和预报（坐标 → 实况）。

选它的理由，按重要性排：

1. **免费，而且不要 API key。** 要 key 的方案意味着每个用的人得自己去注册一个、填进配置里；这个项目
   只是个小扩展，不该把「让你的天气能用」变成一件差事。
2. **它不需要任何新权限。** 这是最要紧的一条，见下。
3. 地理编码支持 `language=zh`，中文界面下搜「上海」拿回的就是「上海」，英文界面下搜 `shanghai`
   拿回 `Shanghai`。

### 为什么加一个联网功能，却不用加 `host_permissions`

Chrome 扩展要在页面里跨域取数据，通常得在 `manifest.json` 里声明 `host_permissions`。**但这里有更要紧的
东西**：一旦声明了新权限，你下次重载扩展时 Chrome 会弹一个确认框，措辞是「读取您在所有网站上的数据」
那个级别 —— 对一个只想显示气温的功能来说，这个代价太大。

而 Open-Meteo 的响应头里带着 `access-control-allow-origin: *`。也就是说扩展页可以直接按普通 CORS 请求
取到它，**一个权限都不用加**。这一点是实测过的（带着 `Origin: chrome-extension://...` 问过一遍），
不是推测。冒烟测试里有一条断言专门守着 `host_permissions` 不许出现。

代价是：**没有权限做兜底**。哪天这个 CORS 头没了，请求就会失败 —— 而且是静默失败。所以失败路径必须做干净。

### 发出去的到底是什么

只有两样东西：

- **你选的城市坐标**（默认上海：北纬 31.22222、东经 121.45806）。就两个数字。
- **你敲进城市搜索框里的那几个字**。

**没有**标签页数据、没有浏览历史、没有设备标识、没有 cookie、没有账号。请求里不带任何能认出你的东西。
想彻底不发，把设置里的天气开关关掉就行。

### 拿不到数据的时候会怎样

这是这个功能设计上最花心思的地方：

- **不报错、不弹提示条、不删缓存。** 断网、被墙、接口挂了，你在新标签页上看到的只是「这里没有天气」，
  而不是一个看不懂也修不了的红条。新标签页是最不该出现错误提示的地方。
- **缓存优先。** 结果缓存在本地 20 分钟。打开新标签页时先用缓存立刻画出来，缓存新鲜就一次网络都不打，
  过期才去回源。所以打开新标签页这个高频动作不会被网络拖住。
- **缓存永不主动删。** 过期只是让它重新拉一次；拉不到就继续显示旧的那份，总比空着强。
- **换城市会丢掉旧城市的缓存。** 不丢的话，页面会拿上海的 26° 配上你新选的「北京」显示出来 ——
  看着一切正常，但它是错的，而且不报任何错。
- **形状不对就当没拿到。** 接口返回的温度如果不是数字，宁可什么都不显示，也不画一个 `0°` 或 `NaN°`
  上去 —— 那种错看起来像真的。

### 天气图标

7 张（晴 / 晴间多云 / 阴 / 雾 / 雨 / 雪 / 雷雨），全部用圆、矩形、直线拼出来，**没有抄任何弧线路径** ——
小尺寸下能靠自己把图元算出来长什么样，而不是赌一段没法验证的 `d` 属性是对的。每一张都在 16px 真渲染
出来看过。接口给的 28 个 WMO 天气码被归成 11 类，强度差别（毛毛雨 / 中雨 / 大雨）抹平了：那一行字没有
那么大地方，而「外面在下雨」这个信息量已经够决定要不要带伞。

## 个性化：`extension/config.local.js`

有些东西只跟你的使用习惯有关，不该混进源码。在 `extension/` 下新建 `config.local.js`（已在 `.gitignore` 里，不会被提交）：

```js
// 把「主页」判定扩到你自己常去的那些站
// 默认规则只认内置几个（Gmail / X / GitHub / YouTube / LinkedIn）
const LOCAL_LANDING_PAGE_PATTERNS = [
  { hostname: 'mail.qq.com' },                        // 只看这个域的根路径
  { hostnameEndsWith: '.example.com', pathPrefix: '/dashboard' },
];

// 自定义分组：把子域并成一张卡，或者按路径拆开
const LOCAL_CUSTOM_GROUPS = [
  { hostnameEndsWith: '.example.com', groupKey: 'example', groupLabel: '示例全家桶' },
];
```

这两组规则的**优先级都高于内置规则**，可以覆盖内置的子域合并逻辑。文件不存在也完全没关系 —— 扩展照常用内置默认值跑，只会在控制台留一条无害的 404。

**匹配字段速查**

- `LOCAL_LANDING_PAGE_PATTERNS`：`hostname` 或 `hostnameEndsWith`（二选一）+ 可选的 `pathExact`（数组）、`pathPrefix`、或自定义函数 `test(pathname, url)`。**都不给路径条件时，只匹配该域的根路径 `/`**。
- `LOCAL_CUSTOM_GROUPS`：`hostname` 或 `hostnameEndsWith` + 可选的 `pathPrefix`，另需 `groupKey`（并组用的 key）和 `groupLabel`（卡片上显示的名字）。

## 工作方式

```
你打开一个新标签页
  -> 页头下面是天气和今天的气温（拿本地缓存先画出来，不为网络等一秒）
  -> 归拢把你开着的标签页按域名摆出来
  -> 主页类站点（Gmail、X 等）单独一组放在最前
  -> 点任意标题跳过去
  -> 看完了的整组关掉（音效 + 彩带）
  -> 舍不得关的先存入「稍后再看」
```

所有逻辑都跑在扩展里。没有服务器、没有账号。稍后再看、钉住的站点、天气城市与设置都存在 `chrome.storage.local`。
唯一一次对外请求是取天气（可关），它只发城市坐标，不带你任何浏览数据。

## 测试

仓库里带了一份冒烟测试 —— 没有依赖、不联网、一秒内跑完：

```bash
node tests/smoke.js
```

它做三件事：用最小 stub 把 `app.js` 装进 Node 的 `vm` 里，直接调用内部纯函数验证行为（子域归并、去重、入口 URL 归一化、TLD 剥离、占位图识别、设置项默认值、天气码映射、缓存新鲜度、搜索失败与「没搜到」的区分……）；给网络和图片做受控的假环境，把各种失败路径一个个造出来；再对源码做静态扫描，守住几条约定 —— 界面文案必须走 `strings.js`、页头版式的不变量、旧品牌名不许回流、天气不许偷偷加权限。

一共 **320 多条断言**，一秒内跑完。

**它不点界面**，也不验证真实 Chrome API 的行为，所以它不能替代你手动加载扩展看一眼。它守的是「逻辑 + 源码约束」，不是端到端。真接口有没有通、URL 拼得对不对，得靠一次真机实测 —— 天气那部分当初就是这么验的。

每条守卫都做过**变异测试**：故意把它对应的代码改坏，确认测试真的会变红。一条永远不会失败的断言不是守卫，只是装饰。

### 想换图标

图标母版是 `extension/icons/icon.svg`，`icon16 / 32 / 48 / 128.png` 全部由它导出 ——
**改图标只改这一个文件**，然后重跑一次导出脚本：

```bash
cd tools && npm i && cd ..    # 只装这一次；依赖关在 tools/ 里，仓库根目录不会被 package.json 污染
node tools/make-icons.js
```

脚本会顺手核验每张 PNG 的实际尺寸和文件名是否对得上，对不上就报错退出。
这一步只在改图标时才需要 —— **平时加载扩展不需要任何构建**。

⚠️ 有一条约束值得知道：**16px 是这个图标真正的战场，不是 128px。**
细线条和窄缝在那个尺寸下会整片消失（五根细签会糊成一条实心条），
所以图形必须画得够粗、缝留得够宽。改完一定要看 16px 那张。冒烟测试里有一条守卫
会检查 `manifest.json` 声明的每个图标文件都存在、且实际像素尺寸和声明一致。
